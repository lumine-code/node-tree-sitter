# Background parsing

The binding supplies portable Wasm languages and native syntax snapshots independently of editor integration.

Each background snapshot includes immutable `changedRanges`, computed on the worker against the previous tree after applying its edits. A fresh parse has no previous comparison and returns an empty array; hosts must invalidate the full relevant extent for fresh parses. A text edit can produce no syntax change, so hosts must also invalidate the edited text ranges. This metadata does not mutate or retain the previous snapshot.

Queries expose lazily computed, frozen `captureNames` and `captureQuantifiers` arrays, plus `patternCount()`. Quantifiers follow the native enum: zero, zero-or-one, zero-or-more, one and one-or-more. Returned matches and individual capture results include `patternIndex`; matches retain `pattern` as the existing alias. Unsupported predicates still reject at construction, rather than being silently ignored by a host.

`loadLanguage(name, bytes)` returns a promise for a language usable with `BackgroundParser`, the synchronous `Parser`, and `Query`. It copies the supplied Buffer before background compilation, so callers may modify or release their original Buffer. Compilation runs on Node's shared libuv worker pool. Languages are scoped to their Node environment and must be loaded separately inside another Node worker.

`new BackgroundParser(language)` creates a lightweight parser handle. Its Wasmtime store and language instance initialize lazily during the first background job, so constructing many injection parsers does not compile their stores on the JavaScript thread. One parser accepts one in-flight parse. The read-only `busy` and `closed` properties expose lifecycle state. Separate parsers can run concurrently within the shared worker-pool capacity. There is no editor-wide priority queue, latest-request coalescing or private thread pool in this library yet. Applications should bound the number of parsers rather than queue an unbounded number of requests.

`parse(text, options)` copies the string into owned native UTF-16 storage before queuing native work. No JavaScript input callback is invoked from a background thread. This first implementation intentionally accepts strings; direct access to Superstring or another native buffer is a separate integration step. Initial input copying and JavaScript edit validation still run on the calling thread and must be included in performance measurements.

`parseSync(text, options)` completes on the calling thread and returns the same immutable snapshot contract immediately. It accepts `previous`, `edits`, `includedRanges` and `revision`; it has no asynchronous cancellation signal. Synchronous and background snapshots can be used interchangeably as `previous`. The handle lazily creates a synchronous parser and rejects overlapping synchronous/background requests. Hosts can therefore load languages and perform initial work asynchronously, then update warm documents synchronously without exposing partial syntax states.

`BackgroundParser.reuseSnapshot(previous, text, options)` can advance a snapshot without parsing when included source text is identical, every boundary keeps its column and all ranges have the same row translation. It returns `null` when that proof fails, including decoder-sensitive boundaries. Successful reuse returns a new immutable snapshot with empty `changedRanges`; the previous snapshot stays valid. Frozen, data-only edit lists may share their validated replay plan across language layers without retaining native trees.

Options are `previous`, `edits`, `includedRanges`, `signal` and `revision`. `revision` defaults to zero and is a nonnegative safe integer supplied by the caller; it is metadata, not an automatic freshness check. The caller must compare it with the current document revision before applying results. `edits` contains sequential `{startIndex, oldEndIndex, newText}` replacements, each relative to the text produced by the preceding edit. The binding validates that they produce exactly the requested new text. A single edit uses a bounded forward coordinate scan. Non-overlapping batches ordered from either end of the document use linear coordinate mapping and materialize the final text once. Other sequential edits use temporary text pieces and newline indexes; that fallback is not a persistent native buffer and can still require quadratic piece traversal for very large dependent edit counts. It derives Tree-sitter row/column edits and applies them to a shallow copy of the previous tree, preserving the published snapshot. All indices and columns are UTF-16 code units; rows count LF characters, including LF in CRLF.

`includedRanges` uses the usual `{startIndex, endIndex, startPosition, endPosition}` objects. Ranges must be ordered, non-overlapping and consistent with the text. Omitting them on the next request restores full-document parsing. The library does not manage a language-injection graph; a future host must schedule parent and child parsers and publish a consistent layer snapshot.

`previous` must be an immutable snapshot returned by this module's `BackgroundParser`, with the same language descriptor. Snapshots can be reused by another background parser in the same environment. Mutable copies and synchronous trees are rejected because their text and edited coordinates cannot be verified as an unchanged revision. Options are read while the parser is reserved; range properties are normalized once before native submission, and validation failures release the reservation. Closing or cancelling from an option getter cannot start a request on a released parser.

Returned snapshots retain immutable `input`, `language`, `revision` and text access. Their `edit()` method rejects. `copy()` returns an independently editable shallow tree copy for callers using the low-level API. A copy retains the original text until its `input` is explicitly assigned new text, which its node text reader then uses; editing coordinates alone never updates text. Use background incremental parsing when text and tree must remain a consistent published snapshot. Nodes keep their originating tree alive and continue to read that tree's original text after later parses. Avoid retaining old nodes indefinitely, since they retain snapshots and their strings. Garbage collection releases trees; individual snapshots do not expose a destructive `dispose()` that could invalidate live nodes.

An aborted signal rejects with an AbortError. `cancel()` requests cooperative cancellation of the current parse. `close()` is idempotent, cancels current work and rejects future requests. Cancellation resets the parser before reuse. Native parsing checks an atomic flag through Tree-sitter's progress callback; it is not a hard real-time interruption of arbitrary external-scanner code. A result cancelled after native completion but before delivery is discarded. Node environment cleanup also requests cancellation; shutdown latency depends on reaching a cancellation point and Node's worker teardown ordering.

Native work never accesses JavaScript handles off-thread. The UI thread can query a delivered native tree while the next parse operates on a separate shallow copy. Wasm grammar code remains in Wasmtime, while syntax trees and query execution are native. Query capture filtering and the upstream JavaScript predicate layer remain synchronous; this package does not yet provide background queries or Lumine-specific scope resolution. Both query operations accept a progress callback, each execution owns its cursor, and recursive use of the same active parser or query rejects. Query compilation errors expose numeric `kind` and UTF-8 byte `offset` fields, including errors at offset zero. Numeric document query bounds and progress indices use UTF-16 code units.

`close()` releases an idle parser's native resources immediately; an active parser releases them when its cancelled job completes. Delivered trees remain valid after closure. `[Symbol.dispose]()` calls `close()` for JavaScript explicit resource management. The low-level synchronous `Parser.parse()` may return null on cancellation, reflected in its TypeScript declaration. Trees and cursors cannot be constructed directly; use parsing, `copy()` and `walk()`.

Syntax nodes also come from parsing or traversal; direct construction, object-spread copies, prototype imitations and proxy wrappers are not valid node arguments. A private class brand is checked before marshalling a node into native operations. Cache registration helpers are internal to the module and are not exposed on public trees. Failed query predicate initialization releases the compiled native query, including unsupported predicates and invalid regular expressions.

This fork does not modify Lumine core, Superstring, display-layer code, dependency pins, grammar packages or the ecosystem catalogue. It does not provide a cross-addon snapshot ABI yet. Those interfaces should be agreed with the concurrent native-core work before editor integration.

Native query cursors and synchronous incremental parsers prevent edits to the tree they are currently reading. Mutating such a tree from a progress or input callback throws; read-only queries and copies remain available. Pattern-index methods reject negative, fractional, non-finite and out-of-bounds indices before entering Tree-sitter. Patterns without text predicates transfer only the emitted capture to JavaScript. Patterns with text predicates transfer a full context when it changes and reuse an exactly equal previous context when possible. Stable string inputs and immutable snapshots also reuse the predicate result; callback input, custom text readers and text accessors are evaluated on every emission. Context comparisons include capture names, node identities and positional context, rather than assuming that a match ID alone uniquely describes the captures. Public capture order, duplicates, properties and distinct result objects are preserved. Changing or growing capture lists can still incur repeated full-context work.

Public tree cursors retain their owning tree through a GC-visible ownership relation. Native references to that tree are weak, so a tree storing its own cursor does not create an uncollectable cycle. The `tree` accessor is read-only and follows `reset()` or `resetTo()` across trees and languages. Editing a mutable tree invalidates its existing cursors: reads and movement reject until the cursor is reset to a current node, or to another valid cursor. Point-based searches recheck their generation after reading argument getters. Snapshots are immutable and do not invalidate their own cursors when a later snapshot is published. Descendant indices are checked against the root of the cursor's subtree, not the whole document.

Synchronous parsers retain logger callbacks through the same GC-visible ownership relation. A callback may refer to its parser without permanently rooting either object. Replacing or disabling the logger releases the previous callback; an otherwise live parser retains its current callback across garbage collection. Node searches that read point or type-list getters reject edits to the tree while those arguments are evaluated.

Low-level callback-backed trees read node text in finite chunks. An empty string or non-string response ends the read and returns the available prefix; no synthetic `undefined` or `null` text is appended. Each callback receives the current UTF-16 position, including after CRLF and supplementary characters. Numeric edits and ranges reject negative, fractional, NaN and overflowing coordinates; positive Infinity remains supported only as an unbounded point coordinate for search operations. Invalid synchronous parse ranges throw instead of silently leaving a previous range set active.

Query indices, match limits and timeouts are validated before conversion to native integers. Positive Infinity is accepted for unbounded point coordinates and `maxStartDepth`, while an unlimited timeout uses zero. Finite query ranges must be ordered; a rejected range never silently expands into a whole-document query. Lookahead state values must fit in an unsigned 16-bit integer; representable but unavailable states keep the native constructor/reset failure behavior.


Node-cache identities include positional context when a tree has shifted views. Ordinary trees retain the compact ID cache; the extra view metadata is allocated only after a nonzero `rootNodeWithOffset()` call. Offset views do not rewrite the text provider. Node display names derived from grammar metadata are assigned as data properties; they are never compiled as JavaScript source. Query execution, incremental parsing and changed-range comparison reject trees associated with another native language instance.

Query predicate strings preserve their explicit UTF-8 length, including embedded NUL characters. Property directives retain arbitrary string keys such as `__proto__` as own data properties. Query pattern source offsets are UTF-8 bytes; document offsets and columns remain UTF-16 code units. Cursor searches by index or position return a child index or `null`, and missing field names/IDs return `undefined`.
